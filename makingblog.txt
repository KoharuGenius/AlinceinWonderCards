## なお、ミニゲームだけだったら…

AIに作らせるのが早いですｗ

いろいろと方法はあるんですが、GeminiのCanvasに、単体 html + CSS + javascript で吐き出させるのが楽ですね。対話して、プレビューしながら作っていけます。

なお、Geminiはわざわざ気を利かせて「Canvas（HTMLのCanvas機能です、めちゃくちゃややこしいｗ）に展開するようにしました！」とか「vue.js ライブラリありき」で作ってくることがありますw 
その方がリッチな演出が可能になりますからね。

しかし後からティラノスクリプトに組み込むわけですから、

「Vanilla JS とDOMの機能だけ、UIはtailwind cssなしでシンプルに作って」

…ってGeminiがガッカリするようなプロンプト投げた方が後々楽になります（笑）。

🤖＜「ホントにそれでいいの？もうちょっとUIギラギラさせましょうよ！」
―という提案もしてきやりがますが、【無視】です！

これくらいであれば、ノーコーディングでサクっとできちゃうことに驚きです。
基本運ゲーであるほど、CPUの思考ルーチンも簡単になるのでお勧めですね（笑）

### ここまでくると…

キャラクターを置いて対戦中にしゃべらせたり、表情を変えたり、ゲームの勝敗によって会話イベントとか発生させたくなりますよね？
ちょっとした対戦中のリアクションくらいだったら、そのままjavascriptにやらせるくらいでいいんですが、その先のサイドストーリーだとか会話イベントがどんどん増えてしまうと、管理しきれなくなってしまいます。


### そこで、ティラノスクリプトです。

もともと、ノベルゲーム用に作られたシステムだけあって、立ち絵を出して表情を変えたり、セリフを言わせるのが得意です。

しかも[iscript]タグや[loadjs]でJavaScriptと連携することができます。さらに、JQueryの機能を使って、レイヤーを直接操作もできちゃって、たいへん柔軟性のあるやつです。


## ゲームのコードを分析してもらう

GeminiのCanvasが吐き出すのは.htmlファイル一本です。こいつをテキストエディタで開いてヒューマンパワーで解析できないこともないのですが…そこもAIで解決させちゃうのも手です。

※2026年10月から、Geminiの無料ユーザーは「Flash-Lite」のモデルしか使えなくなってしまいました…。このことがどう影響するのかは、まだ未知数。


コードをチャット画面に貼り付けるなり、ファイルをアップロードするなりして、「どういうことやってるか教えて？」とでも聞けば、解析レポート出してくれますｗ


## CSSとJavaScript部分を別ファイルにしておく

こいつも手動でやった方が早いこともあるんですが(^-^;

AIを活用することもできます。
たとえば、

・「スタイルシート部分.cssファイルにして」とか、
・「JavaScriptの関数をまとめて.jsファイルにして。ついでに関数ごとのリファレンスも作って

…みたいなプロンプト投げられるかもしれません。

こうして別ファイルにしておくと、ティラノスクリプトで扱う際に
 first.ks 内で[loadcss]、[loadjs]しておくことができるようになります。


ティラノスクリプトは[loadjs]で引っ張ってくる【JavaScriptの関数群.js】を自動的にモジュール化して、
どっからでも
[eval exp="hoge();"]とか
[iscrpit]～[endscript]タグ内で呼び出せます。
いちいちインスタンスとか考えなくてもよくて、アホのように楽であります。

とりあえずはここまで。


## ゲーム盤面をレイヤーに貼る

次にゲーム盤面部分のHTML部分をひっこぬきます。
Geminiに作らせると、意外と(?)コメントがしっかりしているので、手動でエイヤで引っこ抜いた方が早い気がします(笑)

AI活用するなら、「ゲーム盤面部分のHTMLコードを出力して」みたいなプロンプトになるかな？

<header>/<main>/<footer> 構造になっているなら、それぞれ<div>タグに書き換えて
class="game_header" みたいな指定にしてしまいます。

それに応じた.cssファイルも書き換えます

最終的には<div>タグだけで構成されたようなシンプルなHTMLになっていると思います。
このHTMLをティラノ側のレイヤーに描画する.jsファイルを作成しましょう

そんなに長いHTMLでもないことが多いので、テンプレートリテラル（バッククォート `）を使って、直接.jsファイルに登録しちゃった方がいいと思います。

別ファイルから読み込むとかすると、同期の問題とかでややこしいんですよね。
[html]タグを使ってHTML読み込むと、[s]タグ使ったのと同じになっちゃうのは理由があるわけです^_^;。

なので、レイヤーにJavaScriptを使って貼り付けることになります。
ティラノスクリプトの「レイヤー0」はキャラ立たせたり…なんてことが多いので「レイヤー1」あたりにJQueryの機能を使ってappendしていくのがいいかもしれません。


まず、board.js みたいなファイルを作っておいて…

const drawGameboard = () => {
	//同名idがあれば削除
	$("#gameboard").remove();
	
	//ゲームボードを貼り付ける位置をtop,leftで指定
	$('.1_fore').append('<div id="gameboard" style="position:absolute; top:20px; left:20px;"></div>');
	
	//ゲーム盤面部分だけを書く。div タグか main タグあたりで囲まれているはず
	const gameboardHTML = `
	<div>
	…
	</div>
	`;
	
	$("#gameboard").append(gameboardHTML);	
};

こうしてできた.jsファイルもfirst.ks あたりで[loadjs]しておいて、別の.ksファイルから呼び出します。（使われている.cssファイルも[loadcss]しておいてくださいね）

@freeimage layer=1
@layeropt layer=1 visible="true"
[eval exp="drawGameboard();"]

…実行してみると、それっぽい表示が出てくると思います。
「ディベロッパーツール」からたどっていくと、レイヤー1に埋めこまれていることがわかります。
「何も表示されてない！？」と思ったら、背景の色を変えて確認できるでしょう
また、必要に応じて必要ないUIは削っていきます

## この盤面にjavascriptを使ってDOMってやる

今回のシンプルなカードゲームの場合

初期画面表示→カード配布→手札選択→勝敗判定→結果処理

のようなフローになります。

このフローを.ksファイル（ティラノスクリプトのシナリオファイル）にします。
手作業でやってもいいんですが、適当にプロンプト打つだけでも AIが、.ksファイルのひな形的なものを出してくれることがあります。

たとえば、
「カードを配ってから、ゲームの決着がつくまでのフローをティラノスクリプトの.ksファイルにして」

…といった具合ですね。ご丁寧にフローチャートまで作ってくれることもあります
AIってすごいですよね…
